# Intervention / Provenance Log

Record human diagnoses, manual code interventions, changed acceptance criteria, model/runtime changes, and major environment changes during an autonomous milestone.

- 2026-08-30: At operator direction during H2, the acceptance contract now explicitly requires a Codex-operated visual playtest in addition to deterministic Playwright regression routes. This records the clarified product intent that Codex itself must observe successive rendered frames and choose bounded controls. The lane separates Codex-visible screenshots from evaluator-private authoritative state and rejects terminal, source, DOM, web, hidden-coordinate, or predetermined-route access.

- 2026-08-29: At operator direction, H2 changed from an Unreal-specific desktop prototype to a phone-first Babylon.js mobile-web prototype because no dedicated Unreal development host is available and direct phone testing through a temporary URL is the priority. The validated engine/World OS authority boundary and all protected product laws remain unchanged; Unreal is retained as a deferred client option.

- 2026-08-13: PR #1 Codex review identified that a timed-out gate leader could exit before SIGKILL escalation while a stubborn descendant retained inherited pipes. The harness implementation and regression were manually updated in response; product laws and acceptance criteria were unchanged.
- 2026-08-13: A follow-up PR #1 Codex review showed that a stubborn descendant could instead close/redirect inherited pipes, causing timeout cleanup to return before process-group escalation. The grace/escalation logic and deterministic regression were manually updated; product laws and acceptance criteria were unchanged.
- 2026-08-13: The next PR #1 Codex review found two wrapper/restart lifecycle gaps: redirected descendants could survive when the wrapper returned before its escalation deadline, and a hard-killed runner shell could leave its lock-inheriting Python wrapper unreachable. Wrapper escalation, safe stop control, restart recovery, and deterministic regressions were manually updated; product laws and acceptance criteria were unchanged.
- 2026-08-13: The following PR #1 review found that the orphan-recovery regression confused zombie signalability with continued execution on container hosts whose PID 1 delays reaping. Test evidence was changed to authoritative lock ownership plus a distinct live replacement wrapper; production behavior, product laws, and acceptance criteria were unchanged.
- 2026-08-13: The next PR #1 review found that the orphan-recovery regression read replacement-wrapper metadata immediately after the replacement shell acquired its runner lock, leaving a valid startup race. A bounded wrapper-readiness poll was added; production behavior, product laws, and acceptance criteria were unchanged.
- 2026-08-13: At operator direction, the next open restart finding triggered a broader manual H0 lifecycle audit rather than another isolated patch. Zombie-safe runner-lock acquisition, an independent wrapper kernel lease, explicit wrapper/child readiness, early-signal capture, process-group fallback cleanup, and four adjacent edge-case regressions were added. Product laws and acceptance criteria were unchanged.
- 2026-08-13: The next PR #1 review found that restart readiness could accept an unrelated direct runner after its intended replacement died. At operator direction, the fix also covered adjacent child-exit/zombie behavior: readiness is now bound to the spawned shell's identity and running job state, with a deterministic unrelated-runner regression. Product laws and acceptance criteria were unchanged.
- 2026-08-13: The next PR #1 review found that the background runner inherited the supervisor's kernel-lock descriptor, allowing supervisor SIGKILL to leave a false active-supervisor lease. The child descriptor inheritance was removed and a supervisor-death/replacement regression was added; product laws and acceptance criteria were unchanged.
- 2026-08-14: The next PR #1 review found the same private-descriptor ownership defect in supervisor backoff children and the manual-restart replacement. At operator direction, the fix was extended across every supervisor/restart helper rather than limited to the two reported lines, both replacement branches were consolidated, and deterministic backoff/gate/control-wait/replacement SIGKILL regressions were added. Product laws and acceptance criteria were unchanged.
- 2026-08-14: The next PR #1 review found that gate evaluation had been over-isolated: closing fd 8/9 allowed worktree mutation to overlap an orphaned evaluation after supervisor death. The evaluator now retains those intentional serialization leases, parent release is close-only for shared-lock safety, and hard/graceful supervisor-death regressions prove the locks persist only through evaluator completion. Product laws and acceptance criteria were unchanged.
- 2026-08-14: The next PR #1 review found that the restart-note regression could exhaust its trace timeout while restart was still completing a valid recovery/readiness path. The test now uses an explicit control-lock wait barrier and waits for successful restart completion before its bounded trace assertion. Production behavior, product laws, and acceptance criteria were unchanged.
- 2026-08-15: The next PR #1 review found that H0 could pass while its required H1 Text Simulator specification remained a draft with no executable evidence manifest. Before H1 implementation began, its acceptance criteria were finalized and expanded into a deterministic scope/evidence contract, a future H1 gate was committed, and H0 was made to verify both. Protected product laws were unchanged; this intentionally finalized the next milestone's acceptance contract.
- 2026-08-15: The next PR #1 review found that an active evidence check did not retain the control/runner leases after gate-evaluator SIGKILL. At operator direction, the full evaluator-to-runner pipeline was audited: explicit lease delegation was added, completed checks that leave same-session descendants now terminate them and fail closed, and post-gate runner handoff requires fresh locks so a `setsid` escape cannot share evaluator-era ownership. Deterministic regressions cover evaluator death, redirected background work, and escaped sessions; product laws and acceptance criteria were unchanged.
- 2026-08-15: The next Codex review found two adjacent process-state gaps: normal Codex leader completion skipped descendant cleanup, while the new gate cleanup treated zombie-only groups as executable. Cleanup now runs for normal and interrupted Codex exits, and a shared namespace-aware Linux process-state helper distinguishes executable members from harmless zombies. Product laws and acceptance criteria were unchanged.
- 2026-08-15: Follow-up Codex review found that normal-exit cleanup occurred after potentially unbounded stream joins and that selecting a fixed `NSpgid` endpoint failed in different PID-namespace layouts. Cleanup now precedes stream joins, and caller namespace depth is derived from procfs self metadata. Regressions cover stubborn inherited pipes plus outer and nested caller namespace views; product laws and acceptance criteria were unchanged.
- 2026-08-15: The next review found that process-group ownership still allowed redirected `setsid` and double-forked descendants to escape both Codex turns and successful evidence checks. Runner, wrapper, and evaluator boundaries now use Linux child-subreaper adoption plus namespace-aware full-descendant cleanup; shell fallback covers hard wrapper death. Regressions exercise detached sessions, double forks, inherited pipes, timeouts, zombies, and lease release. Product laws and acceptance criteria were unchanged.
- 2026-08-16: Codex follow-up found that evaluator SIGKILL could still release serialization after a check exited if its detached child had closed every inherited lease, and that a post-cleanup numeric process-group fallback could signal a reused ID. The supervisor is now the persistent outer gate subreaper, fallback cleanup rejects evidence before releasing locks, and the stale group signaling path was removed. Product laws and acceptance criteria were unchanged.
- 2026-08-23: The next Codex review found that supervisor/evaluator double death could still orphan descriptor-closing work, and that a failed fallback cleanup released serialization without verification. A dedicated gate watchdog now owns both leases across those failures, retries interrupted cleanup, and leaves a durable marker that blocks every Codex execution entry point after unverified watchdog death. Deterministic regressions cover both findings; product laws and acceptance criteria were unchanged.
- 2026-08-23: Follow-up review found the killed-cleanup-helper regression could wait indefinitely for a platform-dependent `timeout` handoff. The watchdog now publishes its gate-guard PID, and the regression freezes that exact guard before killing the evaluator and guard, providing an explicit transition to the injected cleanup-helper handshake. Production fault containment, product laws, and acceptance criteria were unchanged.
